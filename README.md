## الملخص (Abstract)

**Ledger** هو نظام بحثي-تطبيقي يهدف إلى سد الفجوة بين البيانات المالية غير
المهيكلة ومتعددة الوسائط (تقارير نصية، جداول، رسوم بيانية، شرائح عرض،
تسجيلات صوتية) وبين قدرة المحلل المالي على استخلاص إجابات دقيقة وموثوقة منها
في الوقت الفعلي. يعتمد النظام على معمارية **استرجاع وتوليد معزز (Retrieval-
Augmented Generation – RAG)** موزعة بالكامل على خدمات سحابية بلا خادم
(serverless)، بحيث لا تُخزَّن أي حالة أو ملفات على القرص، ويمكن نشره وتوسيعه
أفقياً بأقل تكلفة تشغيلية ممكنة.

يقدّم Ledger واجهة استخدام أنيقة مستوحاة من التصميم التحريري للمنشورات
المالية الفاخرة، وخط أنابيب معالجة (pipeline) يفهم النص، الصورة، الجدول،
والصوت ضمن مسار واحد موحّد، دون الحاجة لتشغيل أي نموذج تعلّم آلي محلياً.

## الدافع والمشكلة البحثية

يواجه المحللون الماليون صعوبة بنيوية في استخلاص المعلومات من مصادر متعددة
الشكل: تقارير PDF طويلة، جداول بيانات مضمّنة، رسوم بيانية توضّح اتجاهات
السوق، عروض تقديمية للمستثمرين، وتسجيلات صوتية لمكالمات الأرباح ربع
السنوية. أدوات البحث النصي التقليدية لا تتعامل مع هذا التنوع، بينما نماذج
اللغة الكبيرة وحدها لا تملك ضماناً لصحة المعلومة (grounding) دون سياق موثّق.

يقترح Ledger حلاً موحّداً: خط معالجة يستخرج المحتوى من كل نوع وسيط على حدة،
يحوّله إلى تمثيل نصي قابل للفهرسة، ثم يُخضعه لعملية استرجاع دلالي (semantic
retrieval) قبل تمرير السياق الناتج إلى نموذج توليدي، بما يضمن أن كل إجابة
مؤسَّسة على الوثائق المرفوعة فعلياً لا على معرفة النموذج العامة.

## البنية المعمارية للنظام

<p align="center">
  <!-- ضع مخطط البنية المعمارية هنا -->
  <img src="docs/assets/architecture-diagram.png" alt="System Architecture Diagram" width="720">
</p>

يتكوّن النظام من أربع طبقات مستقلة، تتواصل فيما بينها عبر واجهات برمجية
(APIs) بلا أي اعتماد على حالة محلية:

| الطبقة | الوظيفة | التقنية |
|---|---|---|
| **طبقة الواجهة (Presentation Layer)** | عرض الوثائق، محاورة المستخدم، إدارة الجلسة | HTML / CSS / JavaScript ثابت |
| **طبقة الخدمة (Service Layer)** | استقبال الطلبات، تنسيق المعالجة، بناء السياق | FastAPI (وظائف بلا خادم) |
| **طبقة الاستخلاص (Extraction Layer)** | تفكيك الوثائق متعددة الوسائط إلى نص قابل للفهرسة | PyMuPDF، python-pptx، نماذج الرؤية الحاسوبية السحابية |
| **طبقة الاسترجاع والتوليد (Retrieval & Generation Layer)** | الفهرسة الدلالية، البحث المتجهي، توليد الإجابة | Weaviate Cloud، Groq Cloud (نماذج اللغة الكبيرة) |

هذا الفصل الصارم بين الطبقات يجعل من الممكن استبدال أي مكوّن (مزوّد نموذج
اللغة، قاعدة البيانات المتجهية، أو طبقة الواجهة) دون المساس ببقية النظام.

## الميزات الرئيسية

- **استيعاب متعدد الوسائط**: معالجة ملفات PDF (نص، جداول، صور)، عروض
  PowerPoint، صور مستقلة، تسجيلات صوتية، وملفات نصية عادية ضمن مسار واحد.
- **وصف بصري ذكي للرسوم البيانية**: تمييز تلقائي بين الصور التوضيحية
  والرسوم البيانية/الجداول المصوَّرة، مع استخلاص القيم الكامنة فيها نصياً.
- **استرجاع دلالي معزول بالجلسة**: كل مستخدم يعمل ضمن حيّز بيانات معزول
  (session-scoped)، بلا تداخل بين المستندات المرفوعة من مستخدمين مختلفين.
- **توليد إجابات مؤسَّسة (Grounded Generation)**: كل إجابة مرفقة بمصادرها
  الدقيقة (اسم الملف، رقم الصفحة، نوع المحتوى).
- **بنية بلا خادم بالكامل (Fully Serverless)**: لا تتطلب إدارة بنية تحتية،
  ولا تخزّن أي ملف على القرص أثناء التشغيل.
- **واجهة مستخدم تحريرية مصمَّمة خصيصاً**: تصميم بصري مستوحى من المنشورات
  المالية الفاخرة، بعيداً عن القوالب الجاهزة.

## حزمة التقنيات (Technology Stack)

| المكوّن | الأداة |
|---|---|
| إطار العمل الخلفي | FastAPI |
| استخراج ملفات PDF | PyMuPDF (fitz) |
| استخراج ملفات العروض التقديمية | python-pptx |
| قاعدة البيانات المتجهية | Weaviate Cloud |
| نماذج اللغة والرؤية والصوت | Groq Cloud (LLaMA / Whisper) |
| الواجهة الأمامية | HTML5 / CSS3 / JavaScript (ES6) |
| منصة النشر | Vercel (Serverless Functions) |

## التثبيت والتشغيل

### المتطلبات المسبقة

- حساب [Vercel](https://vercel.com)
- عنقود [Weaviate Cloud](https://console.weaviate.cloud)
- مفتاح واجهة برمجية من [Groq Cloud](https://console.groq.com)

### خطوات النشر

```bash
# 1. تثبيت أداة سطر الأوامر الخاصة بـ Vercel
npm install -g vercel

# 2. تسجيل الدخول وربط المشروع
vercel login
vercel

# 3. تهيئة متغيرات البيئة (انظر الجدول أدناه)
vercel env add GROQ_API_KEY
vercel env add WEAVIATE_URL
vercel env add WEAVIATE_API_KEY

# 4. النشر إلى بيئة الإنتاج
vercel --prod
```

### التشغيل المحلي (اختياري)

```bash
pip install -r requirements.txt
uvicorn api.main:app --reload
```

## متغيرات البيئة

| المتغيّر | إلزامي | الوصف |
|---|---|---|
| `GROQ_API_KEY` | نعم | مفتاح الوصول إلى Groq Cloud |
| `WEAVIATE_URL` | نعم | رابط عنقود Weaviate Cloud |
| `WEAVIATE_API_KEY` | نعم | مفتاح الوصول إلى Weaviate Cloud |
| `GROQ_TEXT_MODEL` | لا | النموذج النصي (افتراضي: `llama-3.3-70b-versatile`) |
| `GROQ_VISION_MODEL` | لا | نموذج الرؤية الحاسوبية (افتراضي: `llama-3.2-11b-vision-preview`) |
| `GROQ_WHISPER_MODEL` | لا | نموذج تفريغ الصوت (افتراضي: `whisper-large-v3`) |

## المرجع البرمجي (API Reference)

| الطريقة | المسار | الوصف |
|---|---|---|
| `GET` | `/api/health` | فحص جاهزية الخدمة |
| `POST` | `/api/upload` | رفع ملف واحد أو أكثر ومعالجتها وفهرستها |
| `POST` | `/api/query` | تقديم سؤال واسترجاع إجابة مؤسَّسة على الوثائق |
| `DELETE` | `/api/session/{session_id}` | حذف جميع البيانات المرتبطة بجلسة معيّنة |

**مثال على الاستعلام:**

```bash
curl -X POST https://your-deployment.vercel.app/api/query \
  -H "Content-Type: application/json" \
  -d '{"session_id": "xxxxxxxx", "query": "ما هو صافي الربح للربع الثالث؟"}'
```
